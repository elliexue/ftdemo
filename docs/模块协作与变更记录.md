# 模块协作说明 & 变更记录（给协作者 / 下一个 AI）

本文档 **一份搞定**：别人（或下一个 AI）该在哪写代码、怎么合并、每次做完要记什么。**当前阶段：变更记录里只写「结果摘要」，不写实现过程细节。**

**玩法与资源总览（给策划/新同学）**：`docs/玩法说明.md`；**资源落盘与加载关系图**：`docs/资源分布示意.md`。

---

## 1. 硬性规则（必须遵守）

1. **单次任务只改「一个玩法 / 一块责任区」对应的文件**  
   生成或修改代码时，默认 **只允许** 动下面「模块与文件对照表」里 **同一行或同一子目录** 下的文件。不要把一个玩法的逻辑拆散改到多个无关目录里。

2. **新增独立玩法**  
   - 在 `src/modules/` 下 **新建一个文件夹**（例如 `fishing/`）或 **一个清晰的入口文件**（例如 `FishingModule.ts`），实现 `IModule`（`init` / `update`，可选 `onPointerDown`）。  
   - **只改** `src/modules/Registry.ts`：增加一行 `import` + `modules` 数组里一行 `new XxxModule()`。  
   - 除非该玩法 **必须** 用全局数据，否则 **不要** 改 `src/game/GameState.ts`。

3. **禁止默认去改的范围（除非任务明确要求且在本文件变更记录里写明）**  
   - `src/core/Engine.ts`（渲染、相机、输入总线）  
   - `src/main.ts`  
   - `src/modules/IModule.ts`（接口契约）  
   若确实要改引擎（例如新输入键位、新射线语义），必须在下方 **变更记录** 里单独记一行说明 **结果**（例如：「引擎增加按键 X 供 XX 模块使用」）。

4. **资源**  
   - 目录、槽位、格式、角色动画命名等见 **`docs/资源规划.md`**。  
   - 静态文件放 `public/assets/`；自定义与回退见 `src/config/assetPaths.ts`。  
   - 批量下载示例 GLB：`npm run download-assets`（见 `说明.txt`）。

5. **合并友好**  
   - 避免装饰器、深层魔法封装；优先扁平、可读函数。  
   - 与现有命名风格保持一致（PascalCase 类、`camelCase` 变量）。

## 3. 接口提醒（`IModule`）

- `init(scene)`：放场景物体、订阅等。  
- `update(delta)`：每帧逻辑。  
- `onPointerDown?(hits, event)`：左键射线结果（从近到远）；锁指针时中心为 `(0,0)`。  

完整定义见：`src/modules/IModule.ts`。
